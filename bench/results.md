## Findings and recommendation (2026-09-29, measured under load — see above)

**Recommended primary model: `qwen/qwen3.5-35b-a3b`** (with `reasoning_effort: "none"`), provisional until
the idle re-run (`bench/night.sh`) and the blind Hebrew review (`bench/hebrew-review.md`).

- **Qwen 3.5 35B-A3B.** Median full answer was 2.85 s; 13/16 answers took ≤ 5 s, and one more took 5.02 s. Median time to first token was 0.6 s. It called the search tool correctly 15/16 times; the one miss was Q19 (Rav Kook), where it refused instead of searching. Answers stayed short (median 3 sentences). Thinking only turns off with `reasoning_effort: "none"`: `/no_think` and `enable_thinking=false` are ignored and leave an empty answer after 7.7 s of reasoning.
- **Gemma 4 26B-A4B.** It was the fastest model (57 tok/s, median 2.9 s, 15/16 ≤ 5 s) even though it ran under the heaviest load (load average 13–22). It uses the most memory (+17 GB). **However, it almost never calls the search tool (3/16).** It answers from memory instead and invents facts. For example, it said Tzom Gedalia falls on "כ"ד באלול" and that kiddush levana is said on Friday night. When it is given passages, its answers are short and stay close to the sources. It is a strong backup, but only because our design retrieves in code before the LLM call.
- **DictaLM 3.0 Nemotron 12B.** This is the user's pick for Hebrew quality, but it is too slow as measured: 15.7 tok/s, median 10.1 s per answer, and only 2/16 answers ≤ 5 s. Its time to first token was 2.4 s, which points to slow prompt reading. Qwen ran at 48 tok/s under similar load, so load alone probably does not explain this; the `nemotron_h` hybrid architecture may simply be slow in llama.cpp on Metal. Its behaviour was good: 16/16 tool calls, it refused correctly, and it gave "אין לי מקור לכך" for Q19. However, on Q14 (chocolate) and Q15 (phone) it drew its own conclusions from sources that do not answer the question. **Under CLAUDE.md §3 it is rejected unless the idle re-run meets the targets.** To include it: `bash bench/night.sh qwen/qwen3.5-35b-a3b google/gemma-4-26b-a4b dictalm-3.0-nemotron-12b-instruct`.
- **GLM 4.7 Flash — rejected.** It never stops generating: it runs to the token limit on every question and invents `<|user|>` turns, which is a stop-token or template problem in this MLX 6-bit build. It also slowed to 6–10 tok/s under load. Some answers misattribute sources, e.g. "chocolate → בורא פרי העץ" citing the seif about dates.
- **DictaLM 3.0 24B Thinking — baseline only.** Its reasoning cannot be turned off, so it takes 13 s (median) before the first word. On Q6 the reasoning used up all 700 tokens and it gave no answer.

Not graded here: halachic correctness (the user reviews answers below) and Hebrew quality (see the blind sheet).
